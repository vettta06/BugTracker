# Стратегии развёртывания

## 1. Новые файлы

В ходе работы приложение DevBug было подготовлено к использованию нескольких стратегий развёртывания.

| Файл | Изменения |
|---|---|
| `main.py` | Добавлена переменная `APP_VERSION`, `/health`, `/live` и `/ready` для получения версии приложения и проверки его состояния |
| `k8s/app/backend-v2-deployment.yml` | Создан deployment для второй версии приложения `v2.0.0`|
| `k8s/app/backend-v2-service.yml` | Создан Service для доступа к подам второй версии приложения |
| `k8s/gateway/httproute.yml` | Используется для настройки маршрутизации трафика при реализации Blue/Green |
| `k8s/gateway/httproute-canary.yml` | Создан маршрут для распределения трафика между версиями в соотношении 90/10 |
| `k8s/gateway/httproute-canary-50-50.yml` | Создан маршрут для распределения трафика в соотношении 50/50 |
| `k8s/gateway/httproute-canary-0-100.yml` | Создан маршрут для полного переключения трафика на вторую версию |
| `k8s/gateway/httproute-ab.yml` | Создан маршрут для выбора версии приложения по заголовку `x-user-group` |
| `k8s/gateway/httproute-shadow.yml` | Создан маршрут с фильтром для переноса запросов на вторую версию приложения. |

## 2. Описание видео

| Видео | Стратегия | Что было показано |
|---|---|---|
| Rolling Update | Постепенное обновление | Изменение версии приложения с `v1.0.0` на `v2.0.0`. На видео показана замена подов, отслеживание процесса обновления и проверка новой версии через endpoint `/health` |
| Blue/Green | Переключение между окружениями | Подготовлены два независимых окружения: Blue (`v1.0.0`) и Green (`v2.0.0`). Продемонстрировано переключение всего входящего трафика на Green и откат на Blue изменением HTTPRoute |
| Canary | Постепенное увеличение доли трафика | Продемонстрированы три этапа распределения запросов между версиями: 90/10, 50/50 и 0/100. Для проверки отправлялись запросы к endpoint `/health`, позволяющие определить, какая версия обработала запрос |
| A/B | Маршрутизация по аудитории | Настроена маршрутизация по HTTP-заголовку `x-user-group`. Запросы с заголовком `beta` направлялись на `v2.0.0`, запросы без него -на `v1.0.0`. Результат проверялся через `curl` |
| Shadow | Зеркалирование трафика | Настроено зеркалирование входящих запросов на вторую версию приложения. Основной запрос обрабатывался `v1.0.0`, а его копия отправлялась на `v2.0.0`. Проверены ответы основной версии и логи подов второй версии |
